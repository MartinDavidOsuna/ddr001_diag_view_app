# Android 1.7.5+24 — corregir pointId rechazado

## Causa confirmada

La captura crea Point.id = point-<evidenceUUID>. El serializer anterior enviaba
ese ID como POINT.entityId / payload.pointId, mientras syncPushSchema exige UUID.
El Pixel mostró items[6..13].payload.pointId invalid_string y doce errores más.
Este camino de captura es compartido por MANUAL y BLE; no es un error de pulsos.

## Corrección exclusivamente en la app

Identidad remota determinista UUID v5 para puntos con ID local no UUID.
UUID válidos se conservan. Upload y referencias de evidencia usan la misma
regla. No se modifican puntos locales, valores, muestras, fotos ni checksums
metrológicos. No hay cambios de API, SQL, configuración productiva o firmware.

Lotes fallidos por VALIDATION_FAILED, sin receipt, se reparan de manera acotada:
sólo identidad de puntos y hashes de transporte, conservando batchId/itemId.
Estados ambiguos, confirmados, con receipt o conflictos no se reescriben.

## Validación

- Suite Flutter: 339 pruebas aprobadas.
- Prueba de lote persistido legado: obtiene ACK tras reparación y conserva ID
  local, checksum de muestra, fotos y batchId.
- Guardas impiden reparar lotes ambiguos y en conflicto.
- MANUAL/BLE: fixture Dart adaptado pasa el validador real de API; restaurar
  el ID con prefijo reproduce invalid_string en payload.pointId.
- UUID determinista comprobado con vector independiente Python uuid5.
- API local sin modificar conectada exclusivamente a DDR001_Hidrantes_TEST:
  fixtures sintéticos con UUID aislados y evidencia de prueba reciben HTTP 200;
  todos sus ítems terminan created/exists/accepted en MANUAL y BLE.
- La aceptación TEST no sustituye al ACK del expediente real en producción.

## Uso

Instalar esta APK como actualización, sin desinstalar. En Historial abrir el
mismo expediente y pulsar SINCRONIZAR. No repetir pruebas ni cerrar sesión.
Confirmar Sincronizado. Cualquier error restante debe conservarse para revisión.
